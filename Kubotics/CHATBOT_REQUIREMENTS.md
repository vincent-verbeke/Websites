# Kubotics AI Lead Qualification Chatbot — Requirements & Technical Specification

## 1. Objectives & Business Context
The Kubotics Chatbot is an automated inbound sales and technical qualification agent. Its primary purpose is to convert website visitors arriving via Google Ads, organic search, and AI search engines into qualified sales opportunities with minimal human intervention.

Key targets:
- **Instant Engagement**: 24/7 availability with < 1s initial response time.
- **Automated Lead Qualification**: Identify visitor intent (Humanoid Robotics, Manufacturing Automation, IT Automation, Consulting Test Day).
- **Dual Data Synchronization**:
  - **HubSpot CRM**: Create/update Contact, Company, and Deal with lead status, source UTM tags, and conversation summary.
  - **PostgreSQL Database**: Complete relational storage of conversations, messages, token usage, raw qualification parameters, and audit logs.
- **Meeting Scheduling**: Propose and facilitate calendar booking (e.g. HubSpot Meetings / Cal.com link) once qualified.

---

## 2. Lead Qualification Logic & BANT Criteria
The agent converses naturally, maintaining an executive, technical tone, subtly qualifying the lead against:
1. **Need / Project Scope**:
   - Humanoid robotics exploration vs. active factory/warehouse automation vs. IT/workflow integration.
2. **Authority / Organization**:
   - Visitor role, company name, industry, and location (Switzerland, DACH, Europe).
3. **Timeline**:
   - Immediate (< 1 month), Next quarter, Exploration (6+ months).
4. **Actionable Next Step**:
   - High intent $\rightarrow$ Direct link to book a 30-min discovery call or Test Day on HubSpot Meetings.
   - Low/Informational intent $\rightarrow$ Offer to email the Kubotics Robotics Capability Brief (capturing email).

---

## 3. HubSpot CRM Integration Architecture

### Free HubSpot CRM Capabilities Used:
- **Contacts API**: Create contact (`email`, `firstname`, `lastname`, `phone`, `jobtitle`, `company`, `lead_status`, `hs_lead_status`, `lifecyclestage: "lead"`).
- **Custom Contact Properties**:
  - `kubotics_primary_interest`: Humanoid | Manufacturing | IT Automation
  - `kubotics_ai_summary`: Executive summary generated by the LLM
  - `kubotics_qualification_score`: Score 1 to 10
  - `utm_source`, `utm_medium`, `utm_campaign`, `gclid`
- **Deals API**: Automatically create a Deal associated with the Contact in the "Qualified to Buy" or "Appointment Scheduled" stage when qualification criteria are satisfied.
- **HubSpot Meetings Embed**: Provide direct interactive meeting booking right in the chat widget.

## 4. PostgreSQL Schema Specification

```sql
-- 1. Leads Table
CREATE TABLE IF NOT EXISTS kubotics_leads (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) NOT NULL,
    first_name VARCHAR(100),
    last_name VARCHAR(100),
    phone VARCHAR(50),
    company VARCHAR(150),
    job_title VARCHAR(100),
    country VARCHAR(100) DEFAULT 'Switzerland',
    primary_interest VARCHAR(100), -- 'Humanoid', 'Manufacturing', 'IT Automation'
    qualification_score INT CHECK (qualification_score BETWEEN 1 AND 10),
    ai_summary TEXT,
    hubspot_contact_id VARCHAR(100),
    hubspot_deal_id VARCHAR(100),
    utm_source VARCHAR(100),
    utm_medium VARCHAR(100),
    utm_campaign VARCHAR(100),
    gclid VARCHAR(255),
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 2. Chat Sessions Table
CREATE TABLE IF NOT EXISTS kubotics_chat_sessions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    lead_id UUID REFERENCES kubotics_leads(id) ON DELETE SET NULL,
    session_token VARCHAR(255) UNIQUE NOT NULL,
    user_ip_hash VARCHAR(64),
    user_agent TEXT,
    started_at TIMESTAMPTZ DEFAULT NOW(),
    last_active_at TIMESTAMPTZ DEFAULT NOW(),
    status VARCHAR(50) DEFAULT 'active' -- 'active', 'qualified', 'abandoned', 'escalated'
);

-- 3. Chat Messages Table
CREATE TABLE IF NOT EXISTS kubotics_chat_messages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id UUID NOT NULL REFERENCES kubotics_chat_sessions(id) ON DELETE CASCADE,
    sender VARCHAR(20) NOT NULL CHECK (sender IN ('user', 'agent', 'system')),
    content TEXT NOT NULL,
    extracted_entities JSONB,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

## 5. Frontend Chatbot Architecture (Angular v22)
- **Component**: `ChatWidgetComponent` (standalone, floating trigger button at bottom-right).
- **State Management**: Angular Signals (`isOpen = signal(false)`, `messages = signal<ChatMessage[]>([])`, `isLoading = signal(false)`).
- **UX & Accessibility**:
  - Accessible dialog (`role="dialog"`).
  - Quick-reply action chips ("Book Test Day", "Humanoid Capabilities", "Manufacturing Automation", "Ask a Question").
  - Streaming markdown responses with syntax highlighting for technical specs.
  - Smooth slide-up drawer on mobile, floating popup on desktop.
  - Preserved session history in `sessionStorage` across page navigation.

## 6. Implementation Milestones for Chatbot
1. **Frontend UI Widget**: Angular Signals standalone component with sleek UI, dark mode styling, and quick chips.
2. **Mock / API Service Contract**: Angular service `ChatbotService` handling local session caching, streaming, and REST payload structure.
3. **Backend API Endpoint Spec**: `/api/v1/chat/message`, `/api/v1/chat/qualify`, and `/api/v1/lead/submit`.
4. **HubSpot + PostgreSQL Sync Service**: Secure background dispatching of qualified lead records.
